# pi-home：会话管理与分析

本文是 [PLAN.md](PLAN.md) 的子方案，覆盖「会话」和「分析」两个标签页。数据只来自会话 jsonl 文件，以及 pi-home 自己保存的标签和备注。

状态：方案阶段，未实现。

## 1. 标签页结构

```text
 ⌂ 首页   ☰ 会话   ◔ 分析   ⚙ 预设                         ⟳ 索引 493/493
```

- `1`–`4` 直接切换，`Tab` / `Shift+Tab` 循环切换；鼠标可以点击标签。
- 「分析」下有子页：`总览 · 时间 · 花费 · 模型 · 工具 · 文件 · 项目 · 行为 · 报告`，用 `[` `]` 切换。
- 所有图表都支持下钻：选中一个格子、柱子或扇区后按 `Enter`，跳到「会话」页并带上对应的筛选条件。

## 2. 数据盘点（本机实测）

2026-11-13 在本机对 `~/.pi/agent/sessions` 做了只读抽查：

| 项 | 结果 |
|---|---|
| 文件 | 493 个 jsonl，65 个项目目录，共 1.4G，最早的会话为 2026-09-26 |
| 记录类型 | `message`（角色有 `user`、`assistant`、`toolResult`、`system`、`bashExecution`）、`usage`（`kind: "cache_warm"` 缓存预热）、`custom`、`custom_message`、`session_info`、`model_change`、`thinking_level_change`、`context_edit`；文档中还有 `compaction`、`branch_summary`、`label` |
| assistant 字段 | `durationMs`、`usage.{input,output,cacheRead,cacheWrite,cacheWrite1h,reasoning,cost}`、`model`、`provider`、`thinkingLevel`、`providerThinkingLevel`、`stopReason` |
| toolResult 字段 | `toolName`、`durationMs`、`isError`、`details` |
| 常见 `customType` | `web-search-results`、`subagent_result`、`run-timer-state`（含 `longestRunDurationMs`）、`pi-auto-name`、`telegram-connection-state`、`pi-forge-prompt-stack-state` |

需要注意：用 `jq` 整体解析时，遇到一行含不合法的 UTF-16 代理对转义就中断了，上面的条目计数只是部分结果。索引器要逐行 `JSON.parse`，坏行跳过并计数，不能因为一行出错停掉整个文件。

## 3. 索引结构

索引分三层，存放在 `~/.pi/agent/pi-home/index.json`。条目数增长到数十万时改用 `node:sqlite`。

### L1 会话摘要
字段见 PLAN.md §4.3。另外增加：
- `sizeBytes`
- `badLines`（解析失败的行数）
- `isSubagent`：名称以 `<subagent:` 开头，或由 `subagent_result` 关联得到
- `parentSession`

### L2 事件明细（列式数组，不存正文）

| 表 | 每行字段 |
|---|---|
| `calls`（assistant） | 时间戳、`durationMs`、input、output、cacheRead、cacheWrite、reasoning、cost、模型编号、思考等级编号、`stopReason` 编号、本轮工具调用数、正文字数、思考字数 |
| `tools`（toolResult） | 时间戳、工具编号、`durationMs`、`isError`、结果字数 |
| `users` | 时间戳、字数、汉字占比、图片数、是否含 `<browser-context>`、引用的 skill 名、是否以「继续」等短句开头 |
| `events` | 时间戳、类型（compaction、model_change、thinking_level_change、cache_warm、branch_summary、context_edit）、附加数值（如 `tokensBefore`、预热花费） |

模型名、工具名等字符串放进字典表，事件中只存编号。

### L2 附带的文本派生统计（建索引时算好，正文不入索引）
- `read`、`edit`、`write` 的路径计数；`edit` 的增删行数（比较 `oldText` 和 `newText` 的行数）。
- `bash` 命令的首个词计数，`git` 命令的子命令计数。
- assistant 正文中代码块的语言计数。
- 用户消息的词频 Top 50：用 `Intl.Segmenter('zh', { granularity: 'word' })` 分词，过滤停用词。
- 礼貌词与催促词计数，词表可配置。

规模估算：本机 assistant 和 toolResult 加起来约 1.2 万条以上，列式 JSON 只有几 MB。

### L3 预聚合
加载索引后在内存中构建：
- `日 × 项目 × 模型` 的 tokens、费用、调用数、活跃分钟；
- `周几 × 小时` 的活跃度；
- 工具转移矩阵；
- 全局排行榜。

图表只读 L3，切换时间范围时重新聚合。

## 4. 会话标签页（会话管理）

```text
┌ 会话 ───────────────────────────────────────────────────────────────────────┐
│ / 搜索…  [全部项目▾] [30天▾] [☐子代理] [★] [#标签▾]   排序: 最近活动 ▾   126 个 │
├──────────────────────────────────────────┬──────────────────────────────────┤
│ ● pi-home 方案调研        Pi-extension…  │ pi-home 方案调研                 │
│   opus-5-5 · 72 次 · 2.1M tok · $3.42 · 今天│ ▁▂▅█▇▃▂▁  上下文水位      ▼压缩   │
│ ★ statusline 改造          statusline-pi │ ███▓▓▒░  工具 DNA                │
│   deepseek · 40 次 · 0.8M · $0.21 · 昨天 │ $3.42  ━━━━━━━━━━━━━╸ 累计花费   │
│   <subagent:A-检索>        Pi-extension…  │ 模型 opus 80% · flash 20%       │
│ ...                                       │ 文件 PLAN.md(6) editor.ts(2)    │
├──────────────────────────────────────────┴──────────────────────────────────┤
│ ⏎ 打开  f 分叉  e 设置  r 重命名  t 标签  * 收藏  x 导出  d 删除  space 多选 │
└─────────────────────────────────────────────────────────────────────────────┘
```

功能：
- **列表**：
  - 每行显示名称（无名称时用首条消息）、项目、主模型、调用次数、tokens、费用、最后活动时间；
  - 状态标记：`●` 运行中、`★` 收藏、`⑂` 分叉、`⊂` 子代理；
  - 排序字段：最近活动、创建时间、费用、tokens、时长、调用次数、文件大小。
- **筛选**：项目、时间范围、模型、是否子代理、收藏、标签、有无错误、费用区间、目录是否存在。
- **搜索**：
  - 默认对名称、首条消息、cwd 做模糊匹配；
  - 输入 `?关键词` 时做全文搜索：用 `rg --json` 扫描会话目录（本机有 `/usr/bin/rg`），按文件汇总命中次数，并在详情栏显示命中片段。
- **详情栏**：当前会话的迷你仪表盘（上下文水位线、工具 DNA 条带、累计花费、模型占比、触及文件），按 `Enter` 进入完整详情页（§5.10）。
- **批量操作**：空格多选后可以统一打标签、导出、删除（走 `trash`）。
- **整理助手**：列出可以清理的会话：
  - 没有对话的会话；
  - 父会话已删除的子代理会话；
  - cwd 已不存在的会话；
  - 超过 N MB 的大文件；
  - 名称或首条消息相同的重复会话。
- **元数据**：标签、收藏、备注存在 `~/.pi/agent/pi-home/meta.json`，以会话 id 为键，不写入会话文件。

## 6. 图表组件库（`src/ui/charts/`）

每个组件都是纯函数：`(数据, 宽, 高, 配色) → string[]`，按宽度缓存渲染结果。

| 组件 | 字符和技巧 |
|---|---|
| sparkline | `▁▂▃▄▅▆▇█` |
| 横条 / 竖柱 | 1/8 精度：`▏▎▍▌▋▊▉█` 和 `▁▂▃▄▅▆▇█`；支持堆叠和上下对称 |
| 热力格 | 每格 `██`，或用 `▀` 的前景色和背景色在一行里画上下两格，使纵向密度翻倍 |
| braille 画布 | 每个字符 2×4 个点，用于折线、面积、散点、圆环、雷达、极坐标、小提琴 |
| 华夫图 | 10×10 的 `■` |
| treemap | squarified 布局 + 背景色块 + 截断标签 |
| 箱线图 | `├─┤`、`┃`、`▐▌` |
| 甘特 / 时间线 | 背景色横条 + 时间刻度 |
| 树 | `├─ └─ │` |
| 桑基（简化） | 左右两列标签，中间用 `─━═█` 区分流量粗细 |
| 大数字 | 3×5 方块数字字形 |
| 标签云 | 按频次映射亮度、粗体，并按频次排序换行排布 |
| 坐标轴 / 图例 / 光标提示 | 共用辅助函数；方向键在图上移动，底部显示数值 |

配色与动效：
- 从当前主题（`noctalia`）取 2–3 个强调色，在真彩色下插值出 5–9 级渐变。不支持真彩色时退回 256 色或 16 色。主题检测沿用 pi 的 `terminal.trueColor` 设置。
- 进入页面时柱子生长、数字滚动约 300ms，由定时器驱动 `requestRender`；可以在配置中关闭。
- 鼠标：点击标签和格子，滚轮滚动。pi-tui 组件支持 `handleMouse`。
